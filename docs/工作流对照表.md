## 怎么选（按显存）

| 显存 | 选哪个 | 原因 |
|---|---|---|
| **24GB 及以上** | 不带「低显存」字样的版本 | 低显存版多了 FFN 分块，**反而更慢** |
| **16GB 及以下** | 带「低显存」字样的版本 | FFN 分块把激活值切块，省显存 |

**步数建议**：日常 **4 步**，要画质 **6 步**。8 步画质提升有限但时间翻倍。

## ⚠️ 两个已废弃的坑（别踩）

1. **GGUF 文本编码器不可用** —— 所有 H3 的 GGUF 编码器仓库（eraiko / unsloth）都**没有 mmproj 视觉塔**，
   `ClipLoaderGGUF` 建不出 tokenizer，会直接崩（`TypeError: the JSON object must be str...`）。
   **必须用 safetensors + 官方 `CLIPLoader`。**
2. **`H3SLAAttention` 在驱动 < cu130 的环境必崩** —— 完整因果链（2026-10-13 真机抓到）：

```
驱动太旧（需要 cu130+，实测 cu128）
  → comfy_kitchen 的 cuda 后端 disabled、triton 后端也 disabled，只剩 eager
  → SLA 走 eager 实现，eager 是 O(T²)：0.98MP/124帧 需要 197~611 GiB，直接爆
  → SLA 崩溃后自动回退 dense
  → dense 又走 comfy_kitchen 的 INT8 注意力核，同样要新驱动
  → 最终报 detect_k_anchor kernel launch failed: CUDA driver version is insufficient
```

日志特征（可以用来判断自己是不是踩了这个坑）：
`Found comfy_kitchen backend cuda: {'available': True, 'disabled': True}`

**解决办法：用「无 SLA 版」工作流** —— 把 SLA 节点摘掉，模型从 UNETLoader 直连 SigmaShift。
此时 ComfyUI 回退到 `Using pytorch attention`，完全不碰这些核，可以正常出片（只是慢一些）。
仓库已提供 4 个 `无SLA版` 工作流；等驱动升级到 cu130+ 后再换回带 SLA 的版本。
