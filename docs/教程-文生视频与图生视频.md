# 上手指南：文生视频 / 图生视频 / 参考图锁角色

> 配套仓库：**MiniMax-H3 · N 卡本地部署（8GB 显存起 · 无审查版）**
> 前置：已跑完 `bash scripts/install.sh` 和 `bash scripts/download.sh`
> 目标：从"装完了"到"出片"，并把提示词写到能用的水平。

---

## 0. 开跑前的 3 分钟自检

| 检查项 | 合格线 | 怎么查 |
|---|---|---|
| 显卡 | 8GB 能跑 / 12GB 起步 / 16GB 舒适 | `nvidia-smi` |
| 系统内存 | **32GB 起步**，低显存档建议 64GB | 任务管理器 / `free -g` |
| 硬盘 | 模型放 **NVMe 固态**（放机械盘速度差十倍） | 模型目录所在盘 |
| ComfyUI | 版本 ≥ 0.30.0（原生 H3 节点） | 界面右下角版本号 |
| 节点 | GGUF / SLA / MAINodes / KJNodes 已装 | 界面里节点不报红 |
| 显存策略 | 16GB 及以下启动必须加 `--lowvram` | 启动命令 |

启动命令：

```bash
cd ~/ComfyUI
python main.py --listen                 # 24GB 及以上
python main.py --listen --lowvram       # 16GB 及以下
python main.py --listen --lowvram --use-sage-attention   # 装了 SageAttention
```

浏览器打开 `http://127.0.0.1:8188`。

## 一、把文件放对位置（90% 的报错出在这）

| 类型 | 放哪里 | 备注 |
|---|---|---|
| 主模型（diffusion model） | `ComfyUI/models/diffusion_models/` | 融合 21G / fp8 / GGUF 都放这 |
| 文本编码器 | `ComfyUI/models/text_encoders/` | **决定审查与否的就是它** |
| 视频 VAE | `ComfyUI/models/vae/` | `minimax_h3_video_vae_fp16` |
| 音频 VAE | `ComfyUI/models/vae/` | **必须 fp32**，fp16 会没声音 |
| LoRA（Turbo / 换脸等） | `ComfyUI/models/loras/` | |

不想把几十 GB 复制进 ComfyUI 目录？新建 `extra_model_paths.yaml` 指向外置盘即可，
ComfyUI 支持多路径扫描，省一份磁盘。

> 文件名大小写、后缀要与加载器里选中的完全一致；不同来源的权重**不要混用**
> （官方原版 + 社区量化混搭容易出现形状/数值不匹配）。

## 二、六个节点核对表（每换一次工作流都看一眼）

| # | 节点 | 选什么 | 常见错 |
|---|---|---|---|
| 1 | UNETLoader / Unet Loader (GGUF) | 你下下来的主模型 | 选了模板默认的官方权重 → 报"找不到模型" |
| 2 | CLIPLoader / CLIP Loader (GGUF) | 你的文本编码器 | 选成有审查版了 |
| 3 | VAELoader（视频） | `minimax_h3_video_vae_fp16` | 和音频 VAE 接反 |
| 4 | VAELoader（音频） | `minimax_h3_audio_vae_fp32` | 用了 fp16 → 无声 |
| 5 | 分辨率 / 帧数 | 见下方参数表 | 一上来就冲 1080P |
| 6 | 采样步数 | 融合模型 **4 步** | 用了 20 步，白等 4 倍时间 |

## 三、玩法一：文生视频（T2V）

**用哪个工作流**：`MATLOWAI-01_reference_4step_sla.json`（4 步 + SLA，最快的一档）

**操作**：只给提示词，不接图。首帧/尾帧输入端留空即可。

### 3.1 提示词的写法：写"分镜"，不要写"标签"

这是 H3 和 SD 时代最大的区别。堆关键词效果很差，它更吃**完整场景描述 + 镜头调度**。

❌ 不好的写法（标签堆砌）：

```
一个女人，咖啡馆，下雨，电影感，8k，高质量
```

✅ 好的写法（分镜体）：

```
黄昏的咖啡馆靠窗位置，窗外下着小雨。一位穿米色针织衫的女性正低头搅拌咖啡，
镜头从她的手部特写缓慢上摇至面部，她抬头看向窗外，嘴角微微上扬。
暖色调室内灯光，窗外冷色调环境光形成对比。
背景音：雨声、咖啡杯轻碰声、隐约的爵士乐。
```

区别在于：第二种把 **画面 / 动作 / 镜头运动 / 光线 / 声音** 全交代清楚了。
H3 的音频是和画面一起生成的，**你不写声音它就自己猜**，猜出来十有八九不是你要的。

### 3.2 镜头术语直接用

推、拉、摇、移、跟、升降，H3 都认；英文的 `dolly in`、`pan left`、`crane shot`、`handheld` 也一样。
想要稳定运镜就写明白，别指望它读心。

### 3.3 建议加一段"限制"

把不想要的东西写出来（负面约束），比事后抽卡省时间：

```
不要：画面撕裂、人物面部漂移、手指畸形、过度磨皮、水印、音画不同步。
```

### 3.4 一次是一个连续镜头

H3 擅长"一个镜头拍完"，**不要在一段里塞多个场景切换**。要转场就分段生成再剪。

## 四、玩法二：图生视频（I2V / 首尾帧）

**用哪个工作流**：`MATLOWAI-04_i2v_fl2v_4step_sla.json`（4 步，实测 107 帧 @1152×640 约 25 秒）
或官方的 `01_官方-图生视频-i2v.json`。

| 输入 | 效果 |
|---|---|
| 不给图 | 等于文生视频 |
| 只给首帧 | 首帧图 → 视频（最常用） |
| 只给尾帧 | 生成内容向尾帧收敛 |
| 首帧 + 尾帧 | 两帧之间插值，做"过渡镜头"很稳 |

**首帧图建议**：分辨率和你设定的输出尺寸比例一致（16:9 / 4:3 / 1:1），
不然会被拉伸或裁切；人物主体别贴边。

### 九宫格分镜玩法（本仓库实测做法）

1. 先用文生图/手绘做一张 **3×3 分镜大图**（每格是一个镜头的关键画面）；
2. 把它作为首帧喂给 I2V，提示词里写清"按 3×3 顺序推进的剧情"（分镜脚本）；
3. 模型会按格子的视觉顺序把剧情串成一段连续视频。

> 本地切图工具见工作区里的 `切九宫格.py`（PIL，自动降级安装依赖），
> 也可以反过来把生成的九宫格切成 9 张图，每张单独做 I2V，再用剪映拼接。

## 五、玩法三：参考图锁角色（Ref2VA）

**用哪个工作流**：`MATLOWAI-05_ref2va_4step_sla.json`

这是 H3 最实用的能力：喂进同一个角色的多张参考图（**最多 9 张，建议 3~5 张不同角度**），
就能做到**跨镜头同一个人、同一个声音**——做口播、做系列内容、做虚拟主播，工作量直接砍一半。

经验：

- **参考图的质量比数量重要得多**：5 张清晰的正/侧面照，效果远好过 9 张糊图；
- 还可以配一段语音参考，让声音也保持一致；
- 参考图会同时约束"长相 + 服装 + 画风"，想换衣服就换参考图。

## 六、参数速查

### 分辨率：只认"像素总量"，不认具体宽高

H3 按 megapixels（百萬像素）控制画面预算，同样的 MP 换比例自由度很大：

| megapixels | 4:3 | 16:9 | 说明 |
|---|---|---|---|
| 0.4 | 864×480 | 864×480 附近 | 极速档，最省 |
| 0.6 | 928×672 | 1024×576 | 画质/速度平衡（推荐起步） |
| 0.98 | 1184×896 | 1344×768 | 高清档，慢 |

> 分辨率是**最大的速度杠杆**（约 6~16 倍），比步数影响大得多。
> 先出 480P 看构图，满意了再升 MP 重出，是最省时间的流程。

### 时长：帧数必须落在 `17k+5` 上

- 帧率固定 **24fps**，训练区间约 **124 ~ 362 帧**（≈ 5.2 ~ 15.1 秒）
- 合法帧数：124、141、158、…、345、362（每次 +17）
- 单次最长 **15 秒**，想更长就用下面的"尾帧接首帧"

### 其他

| 参数 | 建议值 | 说明 |
|---|---|---|
| 步数 | 融合模型 **4**；官方权重 8 步 + Turbo LoRA | 更多步 ≠ 更好 |
| CFG | **1.0** | H3 是蒸馏模型，无需 CFG，>1 反而崩 |
| shift（时序） | 视频 12 / 音频 2 | DMAD 类加速 LoRA 的建议值 |
| seed | 固定后微调提示词 | 便于对比不同提示词的效果 |

## 七、做长片：尾帧接首帧

单次 15 秒是硬限制。做 60 秒长片的成品做法：

```
第 1 段（12s）→ 导出尾帧 last_01.png
第 2 段：首帧 = last_01.png，提示词接上一段的剧情 → 导出尾帧 last_02.png
第 3 段：首帧 = last_02.png … 以此类推
最后用 ffmpeg 无损拼接（流拷贝，1 秒完成，不重新编码）
```

- 搭配 **Ref2VA 锁角色**，跨段人物/声音可以保持一致；
- 每段时长建议 8~12 秒，太长中间容易飘；
- **拼接前务必校验文件大小/校验和**（大文件传输被截断是很常见的坑）。

## 八、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 报错找不到节点 | ComfyUI 太老 / 没装 GGUF 节点 | 升级到 0.30+，装 `ComfyUI-GGUF` |
| 加载模型直接崩 / OOM | 量化不够狠 | 换更低档；启动加 `--lowvram` |
| 出片没声音 | 音频 VAE 用了 fp16 | 换成 **fp32** 版本 |
| 有声但音画不同步 | 两个 VAE 接反了 | 回工作流检查连线 |
| 画面崩坏、人物变形 | 量化太狠（Q2/Q3） | 升档位或降分辨率，提示词救不回来 |
| 慢到无法接受 | 模型在机械盘 / 内存不足走虚拟内存 | 挪到 NVMe；加内存 |
| 显存刚好卡在边缘 | 首次加载开销大 | 分辨率降一档先跑通，再逐步升 |
| 生成结果每次都不一样 | 没固定 seed | 固定 seed 做对比 |
