# 模型选择指南（按显卡挑，别盲目下全套）

MiniMax-H3 的模型组合有三个自由度：**主模型（决定画质/速度）**、**文本编码器（决定审查）**、**量化档位（决定显存）**。
三者可以自由搭配，本指南帮你按显卡一次选对。

## 一、先决定两件事

### 1）文本编码器选哪个？（先按体积选，别按文件名选）

| 可选文件 | 大小 | 适用 |
|---|---|---|
| ethanfel heretic **INT8 ConvRot**（safetensors） | 26.4G | ⭐ **本仓库默认**：去审查 + 通用 |
| Momoking heretic **NVFP4**（safetensors） | 15.7G | **仅 Blackwell（50 系）** |
| Comfy-Org 官方 INT8（safetensors） | 27.1G | 通用（官方原版） |
| ~~eraiko / unsloth GGUF（Q2~Q8）~~ | 13.1G ~ 26.7G | ❌ **H3 不可用**：缺 mmproj 视觉塔，`ClipLoaderGGUF` 必崩 |

> ⚠️ **文本编码器只认 safetensors（2026-10-13 真机验证）**：H3 的文本编码器是 Qwen3-VL（多模态），
> 而市面上所有 H3 的 GGUF 编码器仓库都**没有 mmproj 视觉塔** → 构建不出 tokenizer → 直接报
> `TypeError: the JSON object must be str, bytes or bytearray, not NoneType`。
> **GGUF 只能用于主模型**；低显存不是靠"换小编码器"解决，而是靠**卸载**（`--lowvram` / RAM offload）。

> **⚠️ 先说清楚（别被社区说法带偏）**：主模型两者完全一样，**差别只在文本编码器这一个文件**。
> 而文本编码器只做"提示词 → 条件张量"的编码，**不生成文字、不存在"拒答"环节**，
> 所以换 uncensored 编码器**并不会"解锁"内容**——Heretic 作者本人已公开说明这点（见 README「真相」小节）。
> 越狱真正有意义的场景是：**把生成尾层接成 LLM 做提示词改写/增强**。选型时请优先按"体积 + 量化档"来挑，
> 而不是按文件名里有没有 uncensored。

### 2）你有多少显存？

| 显存 | 主模型 | 文本编码器（**必须 safetensors**） | 分辨率 |
|---|---|---|---|
| 8GB | GGUF Q2_K（6.7G） | INT8 ConvRot 26.4G（靠系统内存卸载） | 480P / 5s |
| 12GB | GGUF Q3_K（8.8G） | 同上（卸载） | 480P / 5s |
| **16GB** | **融合 Turbo 21G** 或 GGUF Q4_K（11.4G） | 同上（50 系可换 NVFP4 15.7G） | 576~768P / 5~10s |
| **24GB（4090）** | 融合 21G / fp8 21G / GGUF Q5 | 同上（或官方 INT8 27.1G） | 768P / 10s |
| **32GB（5090）** | fp8 21G **或 NVFP4** | **heretic NVFP4 15.7G** | 768P / 10~15s |
| 48GB（4090-48G 实测） | 融合 Turbo 21G | INT8 ConvRot 26.4G | 0.4~0.98MP / 5s，**54~243 秒** |

## 二、主模型怎么挑

| 需求 | 推荐 | 理由 |
|---|---|---|
| **想要最快** | 融合 Turbo 模型（21GB，4 步） | 已内置 8 步 Turbo 蒸馏 + 运动平滑 LoRA，图生/参考二合一 |
| **想要最清晰** | 官方 `fl2va_bf16`（66G）或剪枝 BF16（40G） | 全精度，细节最好 |
| **显存吃紧** | GGUF Q2_K（6.7G）~ Q4_K（11.4G） | ComfyUI-GGUF 支持分层加载 |
| **要锁角色** | 任何 `ref2va_*` 版本 或融合模型 | Ref2VA 分支支持参考图条件 |
| **50 系想省显存** | NVFP4 权重 | Blackwell 专属，权重减半 |

| Q5_0 / Q5_K | 13.9G | 几乎无损 | 24GB 卡甜点位 |
| Q6_K / Q8 | 16.7G / 26.7G | 无损 | 大显存用 |

| BF16 | 40~66G | 满血 | 48GB+ |

## 四、现成组合（抄作业）

| 显卡 | 主模型 | 文本编码器（safetensors） | 步数 | 预期 |
|---|---|---|---|---|
| **RTX 4060 8G** | Q2_K 6.7G | INT8 ConvRot 26.4G（卸载） | 4 | 480P/5s，分钟级（极限卸载） |
| **RTX 3060 12G** | Q3_K 8.8G | 同上 | 4 | 480P/5s，1~3 分钟 |
| **RTX 4060Ti 16G** | **融合 Turbo 21G** | 同上 | **4** | **11 GiB / 65 秒**（实测） |
| **RTX 4090 24G** | 融合 21G 或 fp8 21G | 同上 | 4~8 | 768P/10s，1~2 分钟 |
| **RTX 5090 32G** | fp8 或 NVFP4 | **heretic NVFP4 15.7G** | 4 | 768P/10~15s，更快 |
| **RTX 4090-48G（魔改）** | 融合 Turbo 21G | INT8 ConvRot 26.4G | 4~6 | **实测 832×480/4步 54s、1344×768/6步 243s** |
| **RTX PRO 6000 96G** | 融合 21G | INT8 / Q8 | 4 | 10s 片 **76 秒**（实测） |

> 最后一档的 4090-48G 是**显存魔改版**（GPU 核心同标准 4090，速度数据可比，显存结论不可套到 24GB 卡）。
> 想用 SLA 加速需要驱动支持 cu130+，否则用仓库里的「无SLA版」工作流（见 README 工作流清单）。

## 五、下载命令

```bash
bash scripts/download.sh                 # 自动按显存推荐
bash scripts/download.sh --vram 24       # 手动指定显存
bash scripts/download.sh --tier balanced # 手动指定档位
bash scripts/download.sh --uncensored 0  # 换官方原版
bash scripts/download.sh --nvfp4         # 50 系用 NVFP4
```
